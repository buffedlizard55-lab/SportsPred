## What each workflow does

### `pages.yml`
Runs on push to `main` and `arena/01a0558a-sportspred`, and on demand.

Verified workflow behavior from the file contents:

1. checks out the repo
2. sets up Node 22
3. configures GitHub Pages metadata
4. runs the full test suite (**120 Node + 23 Python**)
5. runs `python3 scripts/build_data.py --strict`
6. assembles a minimal `_site/` artifact containing only:
   - `index.html`
   - `assets/`
   - `engine/`
   - `data/`
7. uploads that artifact
8. deploys it with `actions/deploy-pages@v4`

Scripts, tests and captured fixtures are deliberately excluded from the public
artifact.

### `collect.yml`
Runs every 30 minutes and on demand.

Verified workflow behavior from the file contents:

1. checks out the repo
2. sets up Node 22
3. runs the full test suite and data validation
4. rebuilds the surface map when possible
5. refreshes the OLBG slate and stores HTML captures for parser review
6. enriches event pages for market lists when reachable
7. tries to collect player statistics without inventing them
8. records/settles predictions from ESPN
9. prints the backtest report
10. commits only `data/` changes, and only when there are actual changes

A failed collection does **not** overwrite the last good snapshot. The workflow
warns instead.

## What you may still need to do in GitHub settings

The repo already has a Pages site at:

- <https://buffedlizard55-lab.github.io/SportsPred/>

If the repository is still configured for **Deploy from a branch** instead of
**GitHub Actions**, switch it:

1. Open **Settings → Pages**.
2. Under **Build and deployment → Source**, choose **GitHub Actions**.
3. Save the change if prompted.
4. Open **Actions** and verify a **Deploy site** run succeeds.
5. Reload the Pages URL and confirm the updated site is live.

## Irregularities / review points

- If Pages stays on legacy branch deployment, `.github/workflows/pages.yml`
  exists but will not become the publishing mechanism until the setting above is
  switched.
- Scheduled collection depends on GitHub-hosted runner egress. The development
  sandbox used to build the repo cannot reach OLBG directly; GitHub Actions is
  the intended place for the live collector to run.
- The Pages workflow publishes the artifact generated by the branch that ran the
  workflow. Because this session is on `arena/01a0558a-sportspred`, deployments
  from that branch are possible while work is in progress.
- The largest model gap remains unchanged: there is still no free verified odds
  feed in the repo (`IR-01`), so deploying the site does not unlock odds-based
  scoring by itself.
